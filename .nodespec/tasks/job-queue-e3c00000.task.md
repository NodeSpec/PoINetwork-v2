## Technology Guidance

_Reference for executing the Implementation Tasks above — apply where relevant. The task list stands even where this guidance is thin._

**Purpose:** Traditional message queuing with flexible routing (direct, topic, fanout, headers exchange types), request-reply patterns, and priority queues. Best for architectures needing complex message routing, delivery guarantees, and per-message acknowledgments. Ideal when routing complexity matters more than raw throughput. Not suited for event replay or log-based streaming; use Kafka for those.

**Best Practices:**
- Use appropriate exchange types for routing patterns
- Configure dead letter exchanges for failed messages
- Implement publisher confirms for reliability
- Use prefetch count to control consumer throughput
- Set message TTL and queue length limits
- Use durable queues and persistent messages
- Implement proper connection/channel management

**Anti-Patterns to Avoid:**
- Not implementing message acknowledgments
- Unbounded queue growth without limits
- Auto-ack without processing confirmation
- Creating too many connections instead of channels
- Using auto-delete queues for important messages

**Freshness:** RabbitMQ 4.x: Khepri (Raft metadata store) replaced Mnesia as the default — the historical split-brain/recovery outage class is addressed; quorum queues are the production default and classic queues legacy; 4.1 (2026-02) advances native streams. Previous inspector schema was host/port connection fields — replaced with architecture decisions.

### Required Steps

#### [toolchain_install] Install RabbitMQ

Install via Docker (recommended) or system package. The Docker image includes the management plugin by default.

```bash
docker run -d --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:3-management
```

#### [dashboard_config] Access Management UI

Open http://localhost:15672 in your browser. Default credentials are guest/guest (only works from localhost). Create a new admin user for production.

**Reference:** http://localhost:15672

#### [permissions] Create Virtual Host and User

Create a dedicated vhost for your application. Create a user with appropriate permissions (configure, write, read) scoped to that vhost. Remove the default guest user in production.

#### [environment_variable] Set Environment Variables

Add RabbitMQ connection details to your application environment.

```bash
export RABBITMQ_URL=amqp://myuser:mypass@localhost:5672/myvhost
export RABBITMQ_USER=myuser
export RABBITMQ_PASS=mypass
```

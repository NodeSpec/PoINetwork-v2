## Technology Guidance

_Reference for executing the Implementation Tasks above — apply where relevant. The task list stands even where this guidance is thin._

**Purpose:** Highly available and scalable DNS web service providing domain registration, DNS routing, and health checking. Supports routing policies including simple, weighted, latency-based, failover, geolocation, geoproximity, and multi-value. Commonly the entry point for all traffic into AWS architectures, routing to CloudFront, ALB, API Gateway, or S3 static sites.

**Best Practices:**
- Use alias records for AWS resources to avoid DNS charges and get faster resolution
- Configure health checks with failover routing for high availability
- Use latency-based routing for multi-region deployments
- Enable DNSSEC signing for domain authenticity
- Use private hosted zones for internal service discovery within VPCs
- Set appropriate TTL values balancing freshness with DNS query costs

**Anti-Patterns to Avoid:**
- Using CNAME records for zone apex domains instead of alias records
- Setting excessively low TTLs causing high DNS query volumes and costs
- Not configuring health checks for failover routing policies
- Managing DNS records manually instead of through IaC

**Suggested File Structure:**
- `terraform/route53.tf` (config)
- `terraform/health-checks.tf` (config)
